## Findings

**Existing pieces (all read-only consult, no edits)**
- `RoomMap` (`src/ui/roomlayout/RoomMap.tsx`) takes `{layout, seatViews, zoom}`. It loads the atlas, builds a draw list, paints one canvas at `bounds*zoom`, and puts `SeatOverlay` over it. It owns its own load/error states (`RoomMapStatus`). Its scroll box is `overflow-auto overscroll-contain` with no max-height. So pan is native scroll only; there is no drag-pan.
- `SeatOverlay` already renders one real `<button>` per seat with an aria-label and a hover/focus name tag (D50). It has **no `onClick` and no `data-seat-code`**. Opening the panel needs a new `onOpen(code)` prop.
- Name-tag hover is `group-hover` only. On touch there is no hover, so the tag shows only on focus. Acceptable for D50, but the tag is cut at the container edge (tagPlacement handles above/below and start/center/end).
- The demo `RoomMapDemo` holds the zoom state and zoom buttons (`roomlayoutCopy.zoomLabel`, `zoomOption`). That UI is demo-only; the room page needs its own zoom control, so extract it into a small `ZoomControl` in `src/ui/roomlayout/`.
- `SeatsPage` (`src/ui/seats/SeatsPage.tsx`) drives the room page. Its panel is already URL-driven through `?seat=<code>` (`parseSeatParam`, `seatHref`, `panelView`). It gets its data from `useRoomSeats` (rooms list, `seatsApi.list`, `seatsApi.get`). `SeatsView` renders the header, the Add button and the seat table; the table row button carries `data-seat-code`, which the post-delete focus logic uses.
- The layout API (`GET /api/rooms/{id}/layout`, `withAuth tier:user`) returns `LayoutResponse`: `{room, version, saved, layout, seatViews, unplaced[], truncated}`. `seatViews[seatId]` is `{state, avatarSeed, name}` and is derived server-side, including `mine` (`o.sub = $3`) and `cannot`. The state union includes `pending`, which is out of scope until SIM-014. There is **no UI client for it**: `src/ui/rooms/` has no layout fetch, and `seats-api.ts` / `rooms-api.ts` need a `layout(roomId)` method. Check how `createSeatsApi` types results (`ok/code`) and copy that. `useRoomSeats` can supply `roomId`.
- Server limits: grid up to 64 tiles. At 32 px per tile and 4x, a 64-tile side is 8,192 px, so 8192 x 8192 = 268 MB RGBA (matches the ticket note). Browsers also hard-limit canvas size (about 16,384 per side and about 268M px area on Chrome, much less on iOS Safari at about 16.7M px). `paintRoom` sets `canvas.width/height` with no cap, and its `getContext` null return maps to the error view. Large canvases on iOS often fail silently with a blank 2D context rather than a null return.
- `layout.saved === false` means the server computed a default layout (unsaved room). `unplaced` lists seats without a tile; those seats are not in `layout.seats`, so they have no button on the map.
- Seat codes in `layout.seats[].code` and `seatViews` keys are seat ids (overlay reads `views[seat.id]`). The seat table is keyed on `SeatDto` from the seats API. Two data sources exist: seats list (`SeatDto`, status from occupant) and layout (`SeatView`). Both must agree; the map uses the layout's own `seatViews`.

## Recommendations
1. **Data**: add `layout(roomId)` to the UI API client and a `useRoomLayout(roomId)` hook (stale-response counter, same pattern as `useRoomSeats`), loaded after the room resolves and refreshed when `refresh()` runs so seat actions (assign, release, cannot-seat) update the map (AC 2: from the derived status). Do not change any server or API code (out of scope).
2. **Mapper** (pure, in `src/lib/sprites/` or `src/ui/roomlayout/`): `LayoutResponse -> {layout, seatViews, unplaced, truncated}` view data, with unit tests (AC 7). Cover: `pending` state mapped to `empty` or rendered as is (decide, see Q1), `unplaced` seat codes, `truncated` flag, an empty layout, an unsaved default.
3. **Zoom cap**: compute the max zoom from the canvas area, for example allow zoom z only when `w*h*z*z*1024 <= ~16M px` (safe on iOS) and each side `<= 8192`. Clamp the current zoom down when the room changes. Default zoom 2x; at 390 px default to 2x and make the scroll box `max-h-[70vh]`. Show a note ("zoom limited for this room size") when levels are disabled. Disabled buttons should use `aria-disabled`/`disabled` plus text. A `paintRoom` failure (a 0 or blank canvas) already goes to the error view; consider a sanity check that `canvas.width` matches the request.
4. **Pan**: keep native scroll on the box (works on touch and keyboard), add pointer-drag pan only if cheap (`touch-action: pan-x pan-y` default; do not use `preventDefault` on touch). Give the scroll region `tabIndex={0}` and the existing `aria-label` so keyboard users can scroll it, as the table does. Make sure the overlay buttons stay focusable inside it and focus scrolls them into view.
5. **Click and keyboard**: add `onOpen(code)` to `SeatOverlay` and `RoomMap`; the page calls `router.push(seatHref(pathname, code), {scroll:false})`, same as the table. `?seat=` on load already works through `panelView`. Add `data-seat-code` to map buttons? Avoid duplicates: the post-delete focus code uses `document.querySelector('[data-seat-code=...]')` and would find the map button first. Use a different attribute (for example `data-map-seat`) or make the focus lookup prefer the table row.
6. **Panel focus return**: check `SeatDetailPanel` returns focus to the opener. With two openers (map button, table row) this needs to be the element that opened it, not a table row lookup.
7. **Keep the table** (AC 6): leave `SeatsView` table as is below the map, in all cases. For `unplaced` seats show the table only (no map button), optionally with a short note "N seats are not on the map" (copy in `src/ui/copy/roomlayout.ts`). Use the table as the accessible alternative to the canvas (map is `aria-hidden`, the overlay buttons are the interactive layer). Optionally a "Show on map" skip link is not needed.
8. **States**: map section shows loading (existing `RoomMapStatus`), error with a retry button (current error says "Reload the page"; a retry for the layout fetch is nicer), and an empty state when `layout.seats` and `fixtures` are empty (an unsaved room: say no map has been drawn yet, and keep the table). Layout fetch failure must not hide the seat table.
9. **Dark mode**: canvas art is theme-independent. Check that the scroll box has a visible border and background from the UI kit tokens (`outline-variant`, `surface`) and that the focus ring and name tag stay visible on dark and light floors. The `SeatOverlay` focus outline is `white` plus a teal ring; on light floors the white outline is weak, so the teal ring carries it. Check `RoomMapStatus` red border in dark mode. Zoom buttons should use `Button`/tokens, not the demo's `border-current`.
10. **Seat state not by colour alone** (AC 2): `SeatOverlay` only draws buttons; the sprite overlays (avatar, blocked sign, mine highlight) come from `buildDrawList` in the canvas. Verify in `placement.ts` / atlas that placeholder frames exist for avatar, mine, cannot and empty so the states are visibly different in the placeholder atlas; if a key is missing `paintRoom` silently skips it (`if (!frame) continue`), so state would vanish. Add a test or a manifest check.
11. **Copy**: add to `src/ui/copy/roomlayout.ts` (or a new `rooms`-level key): map section heading, retry, zoom-limited note, unplaced note, empty-map text, pan hint. Keep `no-literals.test.ts` green (no literal strings in components).
12. **Layer rules**: all new code in `src/ui/**` and `src/lib/**`; import via `@/`; run `pnpm check:layers`, `pnpm typecheck`, `pnpm format:check`, `pnpm test`.

## Risks
- Canvas memory/size limits (security finding 4) on 64 x 64 rooms; iOS Safari fails silently. Mitigate with the area cap above, and ideally a manual test on a real phone.
- Two fetches (seats list and layout) can disagree briefly after an action; refresh both together, and treat the table and panel as the source of the seat's detail (the panel is already fetched fresh per SEA-05).
- Duplicate `data-seat-code` selectors break post-delete focus restore.
- Touch devices: no hover, so name tags are only seen after focus; tapping opens the panel right away, so tags are rarely visible on mobile. This follows D50, so flag it, do not fix it.
- Many seats (`LAYOUT_LIMITS.seats`) means many DOM buttons over the canvas; fine, but the `truncated` flag from the layout API must be shown (reuse `seatsCopy.truncated`-style text).
- Placeholder-only atlas (D58): the map will look rough; do not block on art.
- Vitest runs static markup in node, so pan, focus, pointer and canvas behaviour is manual-test only; keep logic (mapper, zoom cap, clamp) as pure functions so it can be unit-tested.
