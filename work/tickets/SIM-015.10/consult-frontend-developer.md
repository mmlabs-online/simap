**Findings**
- Current EditorCanvas: click layer uses React mouse events (onClick/onMouseMove) on the div. tileOf uses canvasTile(offset, bounds, zoom, w, h), which returns null outside the room. dragDelta in tiles.ts takes raw pixels relative to the room origin and does NOT add bounds.x. Canvas offsets include sprite overhang (bounds can be negative), so a drag must convert both points to room-origin pixels first (offset/zoom + bounds.x)*zoom, or use tile coordinates directly. A cleaner option is a new pure delta on tiles. Do not feed the raw canvas offset to dragDelta; that gives wrong deltas when bounds.x % TILE != 0.
- canvasTile returns null off-room and is unclamped. Marquee and drag need a clamped variant (pointToTile exists but also has no bounds offset). Add `canvasTileClamped` in canvas-point.ts.
- Reducer: "move" already applies moveItems to the whole selection, refuses atomically (checked()) with a `notice` refusal, and does one commit. So drop = dispatch({type:"move", dx, dy}). A refused drop already leaves the draft unchanged, which is the snap back. Only a message check is needed: the notice shows through EditorStatusLine. A missing "snap back" visual is trivial because the ghost is local state cleared on pointerup.
- History: commit pushes one step per call, with no coalescing. Arrow-key coalescing needs a new mechanism (see Recommendations).
- Keyboard: LayoutEditor has one onKeyDown on the wrapper div (bubbling). Only Esc is handled, via escDisarms (armed, no dialog, not defaultPrevented). It sees events bubbled from inputs too (the resize inputs in the inspector), so new shortcuts need an input/dialog guard. The leave dialog is `guard.pending !== null`.
- Armed tool: a click places. The click layer has `tool` branching. Drag and marquee must be disabled while armed (or the pointerdown must be ignored), so the armed ghost and place keep working. `arm` clears selection, and `place` is only on click.
- frozen = readOnly || saving; the reducer already no-ops edits, but the UI should skip starting drags and marquees too.
- No DOM test env: the state machine has to be pure and tested in plain Vitest; EditorCanvas stays thin.

**Recommendations**
1. New pure module `src/lib/layout-editor/pointer-gesture.ts` (+ test), reducer style: `type Gesture = idle | {kind:"press", startTile, startPx, hitKey, additive, onSelected} | {kind:"drag", startTile, delta, keys} | {kind:"marquee", startTile, curTile, additive}`. `gestureReduce(g, event, ctx)` with events down/move/up/cancel and ctx {draft, selection, armed, frozen}. Rules (AC1, AC2):
   - down: ignored if armed, frozen, a non-primary button, or no tile. It enters `press` and remembers the hit item from itemAt.
   - move: stay in `press` until the pointer crosses a threshold (about 4 px, or the tile changed). Then a hit starts a drag and no hit starts a marquee. If the pressed item is not in the selection, dragging selects it alone first (shift keeps the others). The drag moves the whole selection.
   - up: `press` with no movement is the existing click behavior (select/toggle/none). `drag` emits {commitMove dx,dy} only if the delta is not 0, 0. `marquee` emits {select keys, additive} using itemsInRect. An empty marquee without shift clears the selection.
   - cancel/Esc/lostpointercapture: back to idle with no commit.
   Return `{gesture, effect}` so the component just dispatches the effects.
2. Click vs drag: switch the click layer to pointer events (onPointerDown/Move/Up/Cancel) and drop onClick for the non-armed path. Keep onClick only for the armed place, or move the place into the same machine as a "press then up" effect. Be careful not to double fire: a click fires after pointerup, and the click's synthetic event must be swallowed when a drag or marquee ended. Simplest: handle everything in pointer events and remove onClick entirely (keyboard accessibility is unaffected, because the layer is aria-hidden and the Items list/PlacePanel/Inspector are the accessible path).
3. Pointer capture: `e.currentTarget.setPointerCapture(e.pointerId)` on down (only when entering press); release on up/cancel; handle onLostPointerCapture as cancel. Use only the primary pointer (e.isPrimary, button 0). Ignore a second concurrent pointer via the stored pointerId.
4. touch-action: set `touch-action: none` on the click layer only while a gesture is active and, because touch-action is read at pointerdown, this cannot be toggled after the touch starts. So either (a) set `touch-none` only while `tool === null && !frozen` (the drag-enabled state), accepting that touch scrolling of the region is lost on the layer (the region scrollbars still work, and a pan is possible by dragging on empty space only if marquee is off for touch), or (b) restrict drag/marquee to mouse/pen (`e.pointerType !== "touch"`) and keep touch as tap-select with touch-action unchanged. I recommend (b) for this slice and noting the choice; it matches "touch-action only while dragging" safely. Please confirm with Ming.
5. rAF throttle: keep the raw pointer in a ref and schedule one requestAnimationFrame per frame that sets the gesture state; cancel the frame on up/cancel/unmount. The handler in the pure machine computes from the latest point, so up must flush the last position synchronously before computing the commit (do not rely on the last rAF). Only update React state when the tile delta or marquee tile rectangle changes (like the existing hover dedupe).
6. Ghost: render in EditorCanvas next to the selection outlines. For a drag, translate each selected item's outline by delta*TILE*zoom, colored ok/refused by a dry run of moveItems(draft, keys, dx, dy).ok (pure, cheap; memoize on the delta). Reuse the preview styling. A marquee draws a dashed rect from the tile bounds (tile-aligned, or pixel; tile-aligned is simpler and matches itemsInRect). Show a live count only if cheap.
7. Scroll: the canvas is in an overflow-auto region and offsets use getBoundingClientRect of the click layer, which already accounts for scroll. Auto-scroll at edges is out of scope; mention it as a follow-up.
8. Keyboard: put the logic in pure `src/lib/layout-editor/shortcuts.ts`: `shortcutFor(e:{key, ctrl, meta, shift, alt, targetKind, defaultPrevented}, ctx:{dialogOpen, frozen, armed, hasSelection, dragging}) -> Action | null`. Mappings: r/R rotate, Delete/Backspace delete, Ctrl/Cmd+Z undo (shift+Z is not asked, leave it unmapped, not redo), arrows move by 1 tile, Esc (cancel gesture first, else disarm, via the existing escDisarms ordering), Ctrl/Cmd+S save. Guards: skip when the target is input/textarea/select/contenteditable, or a button for Space/Enter only (not needed), when dialogOpen, when defaultPrevented, when alt, and for plain keys when any of ctrl/meta is held. Ctrl/Cmd+S must call preventDefault only when handled, and it must also work in inputs? Prefer to keep it active everywhere except dialogs, since the browser Save dialog is otherwise annoying; flag as an open question. Backspace in an input must never delete items. Arrows on the focused region (tabIndex 0 scroll container) would normally scroll it: preventDefault only when a selection exists and the action runs, otherwise let the region scroll. Handle Ctrl+Z natively in inputs (do not intercept).
   Scope: keep the single onKeyDown on the wrapper (it already covers the canvas region, inspector buttons and palette), not a window listener, so shortcuts do not fire when focus is elsewhere on the page. Caveat: nothing is focused after load, so shortcuts only work once focus is inside the wrapper. Consider autofocus on the canvas region after a click (the pointerdown handler should focus the region with preventScroll) so shortcuts work after a canvas click.
   Buttons: arrows/R/Delete on a focused button are fine; but Space/Enter must not be touched.
9. Undo coalescing for arrows: add to history `commit(h, next, coalesceKey?)` plus a field `coalesce: string | null` in History, or (less invasive) a separate action `{type:"nudge", dx, dy}` and a `nudgeAt` timestamp/key in EditorState. Logic: if the previous commit was a nudge of the same selection (same key list) within about 600 ms, replace present instead of pushing to past (`{past: h.past, present: next}`). Keep time out of the pure reducer: have the component pass `coalesce: boolean` computed from a ref with the last-arrow time and the selection, or define coalescing as "consecutive arrow actions with no other action in between and the same selection" (no clock; simplest and deterministic and testable). Any other action (select, rotate, undo, place, tool change, pointer gesture) must reset it. I recommend the no-clock version: add `lastMove: {keys: string} | null` to EditorState, set by nudge, cleared by every other action case. Undo returns to the pre-sequence state in one step (AC). Edge: a refused arrow must not clear the run. A coalesced run that returns to its starting position leaves a no-op undo step; harmless, and isDirty compares to baseline anyway.
   The drag itself needs no coalescing (one dispatch on up).
10. Visible shortcut list: a small `<details>` or static list in a new component (or in EditorToolbar/Inspector), text in `src/ui/copy/roomlayout.ts` (D36). Source the displayed list from the same table as `shortcuts.ts` so the list and the handler cannot drift; add a test that every mapped shortcut has a copy entry.
11. Tests (R5): pointer-gesture (threshold, click vs drag, armed/frozen ignore, shift additive, cancel, marquee rect either direction, drop with delta 0, press on an unselected item), shortcuts (inputs, dialogs, modifiers, Backspace in input, Ctrl+S, arrows with no selection), nudge coalescing in editor-state (run, break on other action, refused arrow keeps the run, undo is one step), the clamped canvas tile, a static render of the shortcut list and the ghost/marquee classes. Manual 20+ seat run per the ticket.
12. R1/layers: all new pure code in src/lib/layout-editor (pure); components in src/ui/roomlayout. No server imports.

**Risks**
- Double handling of click and pointer events (the swallowed click) creates phantom selects. The pointer-only approach avoids this.
- Without pointer capture a pointerup outside the layer leaves a stuck gesture. Cover lostpointercapture/pointercancel/blur and Esc.
- touch-action and touch scrolling: option (a) harms scroll on the layer; option (b) leaves touch users without drag (the inspector Move buttons remain as the alternative).
- A dragged item that is not selected: confirm the intended behavior (select-then-drag, as designed above).
- Keyboard events from inputs/dialogs bubbling to the wrapper; the Backspace and Ctrl+Z cases are the dangerous ones.
- Browser conflicts: Ctrl+S (needs preventDefault), Backspace (old back navigation), arrows scrolling the region, Ctrl+Z in text fields.
- The rAF callback after unmount, or a stale delta applied after zoom changes mid-drag (zoom control is outside the canvas but can be keyboard-triggered; cancel the gesture on zoom/draft change).
- Large rooms: the dry-run moveItems per tile change runs checked() over all items; it is fine at the item limits but memoize.
- The save races: Ctrl+S while saving must be ignored (canSave covers it).

2. Should Ctrl+S work from inside the resize inputs, or only when the focus is not in an input (ticket says not active in inputs)? I read the ticket strictly: no shortcuts in inputs, including Ctrl+S.
3. Should dragging an unselected item select it first (design above)? And dragging on empty space with shift: add to the selection (additive marquee)?
4. Shift+Ctrl+Z / redo: not in scope (no redo in history); confirm.

6. Arrow with a refused move (edge): message through the existing notice is enough?
