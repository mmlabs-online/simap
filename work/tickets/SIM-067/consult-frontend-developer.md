## Findings

**Current state (all UI-only work is feasible; no API/schema change needed)**
- `MySeatView.tsx` (pure) renders an h2 "My seat", a notice live region, loading/error cards, a single-column `<ul>` of seat cards (code, Room/Group/Project as a `dl`, View on map via `seatResultHref(seat)`, Release), and the empty Card with a `/rooms` link. It then renders the `requests` ReactNode slot.
- `MySeatTab.tsx` owns data and behaviour: `useMySeats`, `useMyRequests` with the `onPage` mark-seen flow (D74; uses `newestDecidedAt` and `markSeen`, never an empty body), release via `ConfirmSeatDialog`, cancel via `cancelOutcome`, `seatTabEmpty`. Keep all of this untouched.
- Requests are rendered by `src/ui/requests/MyRequestsView.tsx`, which also owns the "My requests" heading (via `portalCopy.seat.requestsHeading`), the "New" chip (`newIds`), "Load more" (`hasMore`/`loadMore`, cursor paged, `REQUEST_LIMITS.defaultLimit` 50) and loading/error/empty states. Its only consumers are `MySeatTab.tsx` and `MySeatTab.test.tsx`; the Approvals page does not use it. The `embedded` prop is therefore the only mode in use, so it is safe to restyle in place.
- Request data (`MyRequestDto`) already has `status`, `seat{code,roomCode}`, `createdAt`, `decidedAt`, `decidedBy{displayName}`. The existing row already shows seat line, chip, requested time, decision line and Cancel. The mockup is mainly a visual change plus the filter, count chips and status icons.
- Existing copy: `requestsCopy.statusLabel`, `seatLine`, `requestedAt`, `decidedLine`, `mine.*`, `emptyFor.*` (per-status empty text, reusable for an empty filter result). `formatRequestTime = formatAuditTime` (check it is UTC+7 per D35; the mockup shows "26 Nov 2026, 21:10").
- Gap vs ticket: `decidedLine` gives "Cancelled on <time>" for cancelled rows (no "by", when `decidedBy` is null). Current code shows the decision line for every non-pending status with `decidedAt`, which is fine and matches the existing behaviour. The ticket only mentions approved/rejected, so keep cancelled showing "Cancelled on <time>", or hide it. Decide explicitly and test it.
- Components available: `Card`, `Button`, `Chip` (a static rounded-[10px] chip using secondary-container colours; `color`/`onColor` props allow green/amber), and `FilterChips` in `src/ui/Chip.tsx` (a radiogroup pill segmented control, `bg-primary` when selected, with `ariaLabel`). Icons available in `@/lib/icons`: `chair`, `event_seat`, `meeting_room`, `grid_view`, `history`. The check and arrow icons need verifying with `Grep` in `src/lib/icons.ts`, and any missing one must be added there (only the first 30 matches were seen).
- Mockup details: the segmented control is a flat rounded-rectangle with a white selected pill and accent text, not the filled-primary pill of `FilterChips`. The mockup status chip has a dot (green Approved, amber Pending). Seat cards have an accent tinted icon tile, an "Assigned" green chip, and a grey inset panel with Group/Project in two columns. Rows are separated by dividers inside one bordered card, with a header (title + count chip + subtitle + filter), not one Card per row.

## Recommendations
1. **Layout (AC1, AC4)**: In `MySeatView`, drop the page-level h2 (the tab bar already names the tab; check against SIM-066's header decision). Add a section header "Your assigned seats" with a count chip (`seats.length`). Use `<ul className="grid gap-4 md:grid-cols-2">` (`grid-cols-1` by default covers 390 px). Per card: icon tile (`chair`), code, `meeting_room` icon + "Room <roomCode>", an "Assigned" chip, the Group/Project panel as a `dl` with `grid-cols-2` (keep `dt`/`dd` semantics, "None" via `t.noTag`), and a footer with a top border: the `grid_view` + "View on map" + arrow link (render only when `href !== null`, as now) and the Release button (min-h-11, `disabled={busy}`). Add `min-w-0 break-words` so long codes and names wrap at 390 px.
2. **Requests (AC2, AC3)**: Restructure `MyRequestsView` as one bordered card. Header: h2 + count chip + subtitle on the left, the filter on the right (wrapping below at 390 px). Rows are `<li>`s with a status icon circle (check for approved, `history` for pending, plus an icon for rejected and cancelled; add any missing icons in `src/lib/icons.ts`), the seat line, a status chip, "Requested …", the decision line, and Cancel on pending (right-aligned, wrapping under on mobile). Keep the "New" chip, the `<time dateTime>` elements, the `cancellingId` states, and Load more.
3. **Filter state**: Put the pure logic in a testable helper (e.g. `src/ui/requests/my-requests-filter.ts`: `type MyRequestFilter = "all" | RequestStatus`, `filterRequests(items, f)`) with `useState("all")` kept in the view (or lifted to the tab). Do not reset on reload/cancel. The count chip must show the **total** (`items.length`), per the AC, not the filtered number. Add `hasMore` handling (see Risks). An empty filter result shows `requestsCopy.emptyFor[status]` inside the card; keep `hideEmpty` and the `mine.empty` state for zero requests.
4. **Filter a11y**: The ticket requires keyboard operation. Use the radiogroup pattern like `FilterChips` (`role=radiogroup`/`radio` with `aria-checked`), but note it needs roving tabindex and arrow keys to be a proper radio group; either implement that or use buttons with `aria-pressed` in a `role="group"`, which is operable with Tab/Enter/Space and simpler. Give the group an `aria-label` (`requestsCopy.filterLabel`).
5. **Copy (D36)**: Add to `src/ui/copy/portal.ts` (`seat.*`): `assignedHeading: "Your assigned seats"`, `assigned: "Assigned"`, `roomLine(code)`, `requestsSubtitle: "Keep track of your seat requests, all in one place."`, `filterAll: "All"`, and the filter aria label. Reuse `requestsCopy.statusLabel` for the other filter labels. Keep `requestsHeading`.
6. **Open question defaults**: (1) Add a "Rejected" filter, giving All / Pending / Approved / Rejected / Cancelled, driven from `REQUEST_STATUSES` so a new status is not silently missed. The mockup order puts Cancelled last, so insert Rejected before it. (2) Show all loaded rows and keep the existing "Load more" cursor pagination; no collapse. This is the smallest change and is already server-paged at 50.
7. **Tests (AC6)**: Use `renderToStaticMarkup`, like the existing tests, for the seat cards (code, room, Assigned chip, None vs tag names, href `/rooms/<code>?seat=<code>`, Release, count chip), for the four row variants (pending shows Cancel and no decision line; approved and rejected show "Approved by X on …" and "Rejected by X on …"; cancelled behaviour per the decision above), and for the count chip and heading. Unit-test `filterRequests` and the empty-filter message. For filter interaction (static markup cannot click) either export a small stateful filter component and test it with a react-dom/test-renderer-style helper if one is already used in the repo, or test the pure helper and assert `aria-pressed`/`aria-checked` on the default render. Update `MySeatTab.test.tsx` (it must keep passing: it asserts that the empty state shows once and the requests heading is absent). Check `MySeatView.test.tsx` and `MyRequestsView.test.tsx` for string assertions that the new markup breaks.
8. **Sequencing**: Depends on SIM-066 shared card and tab styles. Do not add a competing card/segmented style. If SIM-066 has not merged, define small local class constants and reconcile afterwards, or base the work on the SIM-066 branch.
9. **Rules**: R1 is fine (UI imports only `lib` and ui). No API calls added (R6/R7 untouched). Format with oxfmt (`pnpm format`), and run `pnpm typecheck`, `pnpm check:layers` and `pnpm test`.

## Risks
- **Filter vs pagination**: Filtering is client-side over loaded pages only. With `hasMore` true, "Approved" may look empty or short while more pages exist, and the count chip shows only the loaded total. Mitigation: show the count as `N+` when `hasMore` (reuse `requestsCopy.summary`-style logic), keep Load more visible under any filter, and consider auto-loading or a hint in an empty filtered result when `hasMore`. Please flag this to Ming.
- **Mark-seen behaviour (D74)**: `onPage` is fed the full item list in `MySeatTab`, not the filtered rows, so filtering does not affect it. Do not move this into the filtered view.
- **"New" markers**: they depend on `newIds`; keep them on rows that are not hidden by the filter. A "New" row hidden under the "Pending" filter is still marked seen; acceptable but worth noting.
- **Time zone (D35)**: confirm `formatAuditTime` outputs UTC+7 in the "26 Nov 2026, 21:10" format; otherwise add a formatter in `lib`.
- **Release during a request cancel**: `busy` disables both; keep this so double actions cannot occur (`acting` ref).
- **Dark theme and contrast**: the mockup's green and amber chip colours need theme tokens (not hardcoded hex); check WCAG AA contrast in both themes (11px text in `Chip`).
- **Icons**: missing icons (check, arrow, door) must be added to `ICON_NAMES` with their glyphs; confirm how `Icon` renders them (font vs SVG sprite) before choosing names.
- **390 px**: the filter with 5 options plus the header will overflow; let it wrap below the title or scroll horizontally.
