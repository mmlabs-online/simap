## Data model / migration
New file `db/migrations/20261126120000_map_items_new_builtin.sql`, expand-only, no table/column/constraint/index change:

1. `create or replace function map_items_seed(p_org uuid) returns void language plpgsql` with the **same signature and
   body shape** as `20261125200000_map_items.sql:57-117` (catalog marker insert, `if found`, one `insert ... values`
   with `(p_org, '<key>', '<name>', '<group>', w, h)` tuples, `on conflict do nothing`), now listing all 59 rows **in
   `LIBRARY_ITEMS` order** (desk.single; fixtures sorted by group then key; floors; chair.office). The six new tuples:
   - `(p_org, 'bin.trash', 'bin trash', 'bin', 1, 1)` — after `desk.single`, before `cabinet.filing`
   - `(p_org, 'chart.flip', 'chart flip', 'chart', 1, 1)` — after `cabinet.filing`, before `elevator`
   - `(p_org, 'clock.wall', 'clock wall', 'clock', 1, 1)` — after `stairs`, before `cooler.water`
   - `(p_org, 'cooler.water', 'cooler water', 'cooler', 1, 1)` — before `door`
   - `(p_org, 'lamp.desk', 'lamp desk', 'lamp', 1, 1)` — before `lamp.floor`
   - `(p_org, 'screen.projector', 'screen projector', 'screen', 2, 1)` — after `rack.server`, before `shelf.books`
   The `members` trigger and `save.ts:84` call the function by name, so they pick up the new body.
2. Backfill for orgs already seeded (one statement, driven by `map_item_catalogs`):
   ```sql
   insert into map_items (org_id, builtin_key, name, group_name, w, h)
   select c.org_id, v.builtin_key,
          case when exists (select 1 from map_items m
                            where m.org_id = c.org_id and device_type_key(m.name) = device_type_key(v.name))
               then v.name || ' (built-in)' else v.name end,
          v.group_name, v.w, v.h
     from map_item_catalogs c
    cross join (values ('bin.trash', 'bin trash', 'bin', 1, 1), ...) as v(builtin_key, name, group_name, w, h)
       on conflict (org_id, builtin_key) do nothing;
   ```
   Conflict target is the primary key only, so a second name clash (the fallback name also taken) raises 23505 and
   aborts the migration instead of skipping silently (A5). Values tuples are written `('key', 'name', 'group', w, h)`
   (no `p_org`) so the sync test can tell them apart from the function body.
3. Nothing else: no `update`, no `delete`, no FK change. The art columns of new rows stay null/0 as for old rows.

Lock/size: about 6 rows × number of orgs, inside the migrator transaction; no lock on existing tables beyond
`map_items` row inserts. Names ≤ 60 chars (longest "screen projector (built-in)" = 27), groups ≤ 40.

Downgrade: forward-only (R2/D3). The previous image keeps working: `toDto` (`src/server/map-items/map-items.ts:41`)
drops rows whose key it does not know, `resolveLayout` drops unknown placed keys, and the old image's trigger calls the
new function body (harmless). New keys are permanent once released (FK `on delete restrict`, rows never deleted), so the
key names in A1 are locked by this migration.

## Assumptions
Each is a default Ming can accept in one line ("A1-A14 ok") or override.
1. **Key names** follow the existing convention group = first segment, name = key with spaces: `bin.trash`,
   `chart.flip`, `clock.wall`, `cooler.water`, `lamp.desk`, `screen.projector` (names "bin trash", "chart flip",
   "clock wall", "cooler water", "lamp desk", "screen projector", like "lamp floor" / "table coffee"). Admins can
   rename. Keys are permanent after release.
2. **Groups**: one new group per object (`bin`, `chart`, `clock`, `cooler`, `screen`); `lamp.desk` joins `lamp`. Five
   additions to `FIXTURE_GROUPS`. (Alternative: one shared `decor` group.)
3. **Blocks / layer**: all on layer `furniture`. Wall clock and projector screen `blocks:false` so they can hang on a
   `wall.face` cell (they do not block a seat or another item either); desk lamp `blocks:false` sub-tile prop like
   `prop.mug`; water cooler, trash bin, flip chart `blocks:true` with shadow (like plants).
4. **Footprints** (rotation 0): projector screen 2×1 (1×2 at 90°/270°); all others 1×1. Admins can resize later (D66 7).
5. **Name collision on backfill**: if an org already has an item whose name equals a new default name (case/space
   insensitive), the new row gets `<name> (built-in)`; if that is taken too, the migration aborts (no silent skip).
6. **Desk lamp is not placeable on a desk** (D61 `layout_fixture_on_desk` applies, as for `prop.mug`); it stands beside
   a desk or on another surface.
7. **All four directions** for every new item, as the pack ships them; e/w of clock and screen are the pack's thin
   side views.
8. **Plant directions dropped** from SIM-042: making `plant.small/large` directional would remove existing frames and
   break rollback (`layout_bad_rotation` on the previous image).
9. **2dPig extras dropped** (vending machine, flags, coloured chairs): SIM-041 found no clear fit; follow-up if wanted.
10. **Anchors** copied from the pack JSON; changed only where a crop shows they are off (noted in `sprite-map.json`).
11. **New rows start visible** (hidden false) with no art override, at the end of their group alphabetically (D67 1).
12. **Rollback window**: a layout saved by the new image with a new item, opened and saved again by the previous
    image, loses those new fixtures (the old image drops unknown keys). Accepted as for any new key.
13. Migration file name `20261126120000_map_items_new_builtin.sql`.
14. No `docs/spec-v1.md` edit: LAY-07 phase-1 wording still holds with D73 recorded in `decisions.md`.
- Hotspots: no other ticket is `IN_PROGRESS`, `REVIEW` or `DONE` (`work/backlog.md`), so no rebase expected.
  `keys.json`, `sprite-map.json` and the atlas are merge-conflict prone for any later art ticket.
