  with a validator (unknown keys, frames outside the atlas, missing directions)." Slice 1 covers the format and the
  validator. The runtime loader is in slice 2.
- Ticket scope: "Placeholder atlas for every key in style guide §7, generated by a script from simple shapes in the §3
  palette (outline and shadow rules applied), checked in as `public/sprites/office.png/json`. The script lives in
  `scripts/`."
- Ticket scope: "Packing script `pnpm sprites:pack`: reads `assets/art/export/*.png` …, computes anchors from the canvas
  size, and writes `public/sprites/office.png` + `office.json`; fails on unknown keys or wrong canvas sizes."
- Ticket scope: "The packing script also reads `assets/art/sprite-map.json` …: cuts each key's rect from its source
  sheet, scales it with nearest-neighbour … Priority per key: `export/<key>.png` > sprite map > code-drawn placeholder.
  Missing keys fall back to the placeholder."
- Ming's note (2026-11-20), which overrides the ticket's "bottom-aligns": "Place pack sprites by the map's `anchor`
  ([x, y] in the rect of the footprint's top-left pixel), not by bottom-alignment; accept the map's `wall.*` tile keys
  as the wall set; source sheets are git-ignored (M-10), so a missing sheet falls back to the placeholder and must not
  fail the build or CI. Directions: pack front/back/left/right = s/n/w/e."
- D55: "The packing script places pack sprites by the map's `anchor` (pack sprites overhang their footprint), accepts
  the pack's wall-tile keys (`wall.*` in the sprite map) as the wall set, and falls back to placeholders when a source
  sheet is absent."
- D54: "cutting is done by the packing script from `assets/art/sprite-map.json`, not by hand. Keys with no source keep
  placeholders."
- Style guide §8: "Export convention: … Canvas width = tiles wide × 32; canvas height = tiles deep × 32 + 16 px headroom
  on top for tall things … The bottom edge of the canvas is the bottom edge of the footprint tiles. … Sub-tile props …
  use a tight canvas and are placed by code." Also "1 px transparent gap between frames", and "`anchor` = offset in px
  from the tile's top-left to the sprite's top-left".
- Style guide §4: "Outline: 1 px `#2a3140` around the silhouette of every object." and "Shadows: … drawn on the floor
  layer, not baked into the sprite."
- Spec LAY "Visual style": "No game engine or new library: DOM or plain canvas (stack unchanged)."

## Approach
1. **Check the sheets first** (risk from the architect consult). Write a one-off check with `readPngSize` plus the
   colour-type and interlace bytes for the 10 sheets in `assets/art/sources/imersa-office/`, and record the result in
   `impl-log.md`. If any sheet is interlaced or 16-bit, add Adam7 or 16→8-bit support to `png.mjs`, which costs about
   40 lines. Do not add a dependency.
2. **Registry `keys.json`.** Use flat frame keys. Directional groups list `.n/.e/.s/.w` with e/w tiles swapped from
   s/n. Defaults, where §7 and the sprite map do not say otherwise:
   - Floors (layer `floor`, 1×1, blocks false, shadow false): `floor.carpet`, `floor.carpet.alt`, `floor.lavender`,
     `floor.wood`.
   - Walls (layer `wall`, 1×1, blocks true): `wall.face.shade`, `wall.base` from §7, plus the 22 `wall.*` keys of the
     sprite map, which already include `wall.top`, `wall.face` and the corners (D55).
   - Openings (layer `wall`, blocks true): `door` directional, s/n `[1,2]`; `window.double` `[2,1]`;
     `partition.glass` `[1,1]`; `window.single` and `window.single.top` `[1,1]` (default, see Assumptions).
   - Furniture (layer `furniture`, shadow true): `desk.single` dir `[2,1]`, blocks true; `desk.pair` dir `[2,2]`, blocks
     true; `chair.office` dir `[1,1]`, blocks false; `cabinet.filing` dir `[1,1]`; `shelf.books` `[2,1]`;
     `rack.server` `[1,1]`; `table.meeting` dir `[3,2]`; `table.coffee` `[2,1]`; `sofa` `[2,1]`; `whiteboard` `[2,1]`;
     `lamp.floor` `[1,1]`; `plant.small` and `plant.large` `[1,1]`; `stairs` and `elevator` `[2,2]` (shadow false);
     `label.sign` `[1,1]` (blocks false, shadow false). All the others block.
   - Devices and props (layer `furniture`, sub-tile, blocks false, shadow false): `device.monitor`,
     `device.monitor.dual` and `device.laptop` directional (the map ships 4 views of monitor and laptop, and §7 allows
     "+ facing"); `device.pc`, `device.phone`, `device.other`, and `prop.keyboard|mouse|mug|papers` single.
   - Overlays (layer `overlay`, sub-tile): `state.cannot`, `state.pending`, `state.mine.tint`; and `marker.blocked`
     (1×1, blocks true).
   - Avatars (layer `avatar`, sub-tile, 32×32 cell): `avatar.body.front|back`, `avatar.hair.{1,2,3}.front|back`,
     `avatar.shirt.front|back`.
   - `scene.signin` is left out ("composed from the above"; the sprite map lists it as "composed later").
3. **Types and validator** (`src/lib/sprites/*`, `src/lib/validate/sprite-manifest.ts`). These are pure, with no I/O
   (R1, `src/lib/README.md`). The validator checks:
   - `tile === 32`, and `layers` deep-equals `LAYERS`;
   - `frames` keys ⊆ `FRAME_KEYS` (unknown → error) and ⊇ `FRAME_KEYS` (missing → error; a directional group missing a
     direction gets a message naming the direction);
   - per frame: integer `x, y ≥ 0`, `w, h > 0`, `x+w ≤ atlas.w`, `y+h ≤ atlas.h`, an integer pair `anchor` (may be
     negative), a positive-integer pair `tiles`, and a boolean `blocks`;
   - optional `meta` is an object; any other top-level key is an error.

   The atlas size is an argument: the runtime loader (slice 2) passes the image's natural size, and the tests pass the
   IHDR size. That keeps the §8 JSON shape unchanged except for the optional `meta`. The `layer` and `shadow` of a key
   come from the registry, not from the manifest.
4. **Codec and raster** (`scripts/sprites/png.mjs`, `raster.mjs`) as in the Files table. These are Node built-ins only,
   with JSDoc types in the style of `check-layers.mjs`. Read `keys.json` and `sprite-map.json` with
   `readFileSync` + `JSON.parse`, not JSON import attributes.
5. **Placeholders** (`placeholders.mjs`). A small table of rect lists per group in §3 colours. Desks use top
   `#f6f5f2` and front `#d8d3ca`; chairs use the teal ramp; walls use top `#8b95a7` and face `#eef1f5`/`#dfe3ea`; floors
   use their zone colours with a 1 px line tone; overlays use the state colours, with the pending bubble a rect plus a
   "!" made of pixels; avatars use greys `#e6e6e6`/`#bdbdbd`/`#8f8f8f` with a `#2a3140` outline. Rules:
   - Tiled keys: canvas `tiles.w·32 × tiles.d·32`, plus 16 px headroom for tall groups (desk, chair, plant, cabinet,
     shelf, rack, lamp, whiteboard). The anchor follows the export rule.
   - Sub-tile keys: a tight canvas, with the anchor centred horizontally and the bottom on the tile bottom.
   - Outline on everything except floors and walls. No baked shadow (§4).

   The art only has to be recognisable and distinct per direction (for example the chair back is drawn on the side
   facing away from the view).
6. **Packer** (`pack.mjs`). For each key in sorted `FRAME_KEYS`:
   - (a) `assets/art/export/<key>.png` if present. Unknown export filenames are a hard error (`.gitkeep` and non-PNG
     files are ignored). The canvas must be `w = tiles.w·32` and `h ∈ {tiles.d·32, tiles.d·32+16}`; the anchor is
     `[0, -(h - tiles.d·32)]`. Sub-tile exports must be ≤ 32×32 with anchor `[floor((32-w)/2), 32-h]`.
   - (b) Otherwise, a sprite-map entry whose sheet file exists, when `useMap`. Crop `rect`, apply `scaleNearest(scale)`,
     and set the anchor to `[-ax·scale, -ay·scale]`, or `[0,0]` when the map has no anchor. The frame is the cut rect
     itself, with no re-canvasing. A map key not in the registry, or a map `tiles` that disagrees with the registry, is
     a hard error. A missing sheet warns once per sheet. A sheet that is present but cannot be decoded is a hard error.
   - (c) Otherwise, the placeholder.

   Then:
   - Shelf-pack: sort by height descending, then key; fixed width 1024; 1 px gap; atlas height = used height.
   - Write `office.png` and `office.json`: sorted frame keys, `JSON.stringify(…, null, 2) + "\n"`,
     `meta = { generator: "scripts/sprites-pack.mjs", version: <first 12 hex of sha256(png)>, sources }`.
   - Validate the result with the same rules as the TS validator before writing. The test in step 7 imports the TS
     validator; the packer re-checks bounds and keys itself in about 10 lines so it does not import TS.
   - **Overwrite guard:** if `<outDir>/office.json` exists and any key with source `"map"` or `"export"` there would
     become `"placeholder"`, refuse and exit 1 unless `--force`. `--no-map` counts as intent to drop the map sources
     and skips the guard for `"map"`.

   Placeholders are never written to `assets/art/export/`. This deliberately departs from the ticket's "produced into
   the same folder first": generated files there would outrank the sprite map under the ticket's own priority rule
   (architect finding 1).
7. **Generate and commit the atlas.** Run `corepack pnpm sprites:pack --no-map` and commit `public/sprites/*`. Then run
   the full pack once into a temp dir (`--out`) on this machine, which has the sheets, to verify AC 3 manually. Record
   in `impl-log.md` the 55 map keys reported as `"map"` and a look at the PNG. Do **not** commit that output (M-10
   default, see Assumptions).
8. **Docs.** Make the `docs/art/style-guide.md` §7/§8/§8b edits listed in the Files table, and add the `CLAUDE.md`
   command line.
9. Run all checks.

Rules applied:
- R1: pure code goes in `src/lib`, with no imports from `scripts/` or `src/ui`. Scripts sit outside `src/`, so
  `check:layers` does not scan them.
- R3: no env and no secrets.
- R4: only the files in the table.
- R5: tests are listed above.
- Stack: no new dependency. A codec on `node:zlib` is repo code, and the spec says "No game engine or new library".

## Specialist input used
Adopted:
- Architect:
  - One shared key registry as JSON (`keys.json`), read by both TS and `.mjs`. Flattened to frame keys, so there is no
    duplicated derivation logic.
  - Hand-written PNG codec on `node:zlib` instead of `pngjs` (no stack change). Check the sheet IHDRs first.
  - Placeholders stay in memory and are never written to `export/`.
  - Priority and fallback semantics: a missing sheet warns, malformed input fails.
  - Optional `meta` with per-key `sources`.
  - CI validates the committed atlas instead of repacking.
  - Overwrite guard.
  - The manifest keeps §8's shape, and the atlas size comes from the PNG rather than a new `size` field.
- Architect and frontend: the anchor convention. Draw = tile top-left + anchor, anchor may be negative, and manifest
  anchor = −(map anchor × scale), pinned with `desk.single.s` → `[-2,-21]`. `docs/art/mockups/render-c302-preview.ps1:25`
  draws at `fx - anchor.x`, which confirms the sign.
- Frontend:
  - Per-frame `tiles` (e/w footprints swapped).
  - Deterministic shelf packer with a 1 px gap.
  - Validator returns a typed error list rather than throwing.
  - `meta.version` for cache-busting in slice 2.

Rejected or changed:
- Frontend "add `size` to the manifest": not needed, since the atlas size comes from the PNG (the IHDR in tests, the
  image's natural size at runtime).
- Architect "commit the atlas with Imersa pixels": a Ming decision. The safe default is applied (Assumptions A1).
- Frontend `KNOWN_KEYS` in a TS file: replaced by `keys.json`, because the `.mjs` packer cannot import TS without
  flags.
- Validator location `src/lib/sprites/manifest.ts`: moved to `src/lib/validate/sprite-manifest.ts`, because CLAUDE.md
  R1 says "validators in `src/lib/validate/`".

Deferred to slice 2 (with defaults recorded in the Split proposal): the renderer choice, avatar tinting, the
rotation→direction mapping, `z`/sort order, name tags and the demo page.

## Assumptions
- **A1 (Ming decision, non-blocking, default applied): committed atlas = placeholder-only.** The Imersa licence forbids
  redistributing the assets, the repo is public, and M-10 is on hold. CREDITS.md says "Built output that ships inside
  the app (atlas, previews) is allowed", but a cut atlas in a public repo can be read as redistribution, and D45 assumed
  "the repo stays private".
  - Default: commit the `--no-map` build. A CI test (`committed atlas is placeholder-only`) stops an accidental commit
    of the Imersa build. The full Imersa atlas is built locally with `pnpm sprites:pack`.
  - Why this does not block: the code is identical either way. Only the committed bytes and one test differ, and
    nothing user-facing ships in this ticket.
  - If Ming allows the Imersa build in the repo: run `pnpm sprites:pack`, commit the result, delete that one test, and
    add the credit line once the art reaches users.
  - Note: `docs/art/mockups/c302-phase1-preview.png` already contains Imersa pixels in the repo.
- **A2 (non-blocking): `window.single` and `window.single.top` are accepted keys.** D55 accepts only `wall.*`
  explicitly, but both keys sit in the sprite map Ming reviewed through the C302 preview, and CREDITS lists "window".
  Dropping them would make the packer fail on the map. Recorded in style guide §7.
- **A3: §8 example anchor `[0, 8]` is a typo for `[0, -8]`.** The text says "offset from the tile's top-left to the
  sprite's top-left". The desk is 40 px tall on a 32 px footprint, and the chair example `[5, -4]` follows the same
  sign. Fixed in the doc.
- **A4: extra directional frames** for `device.monitor`, `device.laptop`, `cabinet.filing` and `table.meeting` follow
  the sprite map (§7 says "1 (+ facing)" / "1–2"); `device.monitor.dual` follows `device.monitor`. Footprints for keys

## Split proposal
The ticket's full scope is about 2,500 lines: about 1,500 in the atlas pipeline with tests, and about 1,000 in the
renderer, compositor and demo with tests. That is more than one implement/review cycle.

**Slice 1 (this plan, SIM-024):** key registry, manifest types and validator, PNG codec, placeholder generator,
`pnpm sprites:pack`, committed placeholder atlas, and docs. It covers ticket AC 1 and the validator part of AC 6.
Slice 1 is itself above the ~400-line guide, mainly from tests and placeholder shape data. It is kept whole because the
committed atlas needs the codec, placeholders and packer together.

**Slice 2 (proposed SIM-024.1, "Room map renderer, avatars, name tags and dev demo").** D55 names the "renderer and dev
demo page", so the lift covers it; the orchestrator should confirm. It covers ticket AC 2, 3, 4, 5 and the hash and
placement parts of AC 6. These defaults are settled now so slice 2 does not reopen them:
- **Renderer: plain canvas for the art plus an unscaled HTML overlay for seats and name tags** (architect; spec allows
  "DOM or plain canvas").
  - The canvas backing size is `W·32·zoom × H·32·zoom`, with `imageSmoothingEnabled = false`, `ctx.scale(zoom)` and
    `image-rendering: pixelated`. This guarantees crisp integer zoom (AC 2) with no CSS-transform or mask edge cases.
  - Tinting is trivial on an offscreen canvas and needs no `data:` URLs, which matters for the SIM-027 CSP.
  - Focus, tab order and tags live in the HTML overlay, which removes the frontend consult's reason for DOM.
  - A pure `buildDrawList(layout, manifest)` in `src/lib/sprites/placement.ts` returns ordered draw ops, so placement
    and order are unit-tested.
  - Known risk: fractional DPR (125%/150%) can soften the image. Check manually and note it in the PR.
- **Rotation → direction:** 0 = `s`, 90 = `e`, 180 = `n`, 270 = `w`, in one table `ROTATION_TO_DIR`. This follows the
  sprite map `_doc`, "a chair rotated 90 deg uses the 'right' view", over the architect's guess of 90 = w. The
  footprint comes from the selected frame's `tiles`.
- **Draw order:** layers in `manifest.layers` order. Within `furniture`, sort by (footprint bottom row, full-tile
  before sub-tile, x, id). No `z` field for now; it becomes a follow-up for SIM-015.1 if needed.
- **Shadow:** drawn by code, not baked. A band 4 px tall starting 1 px above the footprint's bottom edge, inset 2 px,
  `rgba(32,42,58,.18)`, for registry `shadow: true` keys (§4).
- **Avatar:** FNV-1a 32-bit of `sub` with per-ramp salts (`sub+":skin"` etc.), picking from the §5 ramps; hair style
  1–3. The view is `back` when the chair frame is `.n`, otherwise `front`. Tint by drawing the grey frame, applying
  `multiply` with the ramp colour, then `destination-in` with the frame. The result is cached per (frame, colour).
- **Overlays:** a pure `overlayFor(state)` maps to `{key, target: "desk"|"chair", offset}` (pending bubble above the
  chair, cannot sign on the desk, mine tint over the desk). Selection, hover and focus use an HTML outline (§6).
- **Name tags:** seats are `<button type="button">` in DOM order (row, column) with an `aria-label` from
  `src/ui/copy/roomlayout.ts`. The tag is `aria-hidden`, shown via `group-hover:`/`group-focus-visible:` only (D50),
  at `px·zoom` in the unscaled overlay, and flipped below when `tileY < 2`.
- **Loader:** `fetch("/sprites/office.json", { cache: "no-cache" })`, then the image `/sprites/office.png?v=<meta.version>`,
  then `validateSpriteManifest(json, naturalSize)`. Failure renders an error state from copy.
- **Demo:** `src/app/dev/roommap/page.tsx` with the `notFound()` guard copied from `src/app/dev/shell/page.tsx:12`, zoom
  1×/2×/3× (no "auto": not in scope), and a fixture in `src/lib/sprites/fixtures.ts` with every seat state and at least
  3 subs. The provisional `RoomLayout` type is kept minimal and marked provisional for SIM-015.1.
