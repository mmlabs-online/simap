## Goal
Give the room map a sprite system: an atlas + manifest that follows the style guide, placeholder art for every key,
and a renderer that draws a room from data, so the map tickets can start before Ming's final art and the final art can
replace the placeholders without code changes.

## Scope reference
`docs/art/style-guide.md` (sections 2, 3, 6, 7, 8); spec LAY "Visual style", LAY-06; decisions D41, D43, D44, D46,
D48, D50, D51, D52, D54, D55. D47 is lifted for this ticket only (D55).

## Scope
- Manifest format and loader exactly as style guide §8 (`public/sprites/office.json` + `office.png`), with a validator
  (unknown keys, frames outside the atlas, missing directions).
- Placeholder atlas for every key in style guide §7, generated by a script from simple shapes in the §3 palette
  (outline and shadow rules applied), checked in as `public/sprites/office.png/json`. The script lives in `scripts/`.
- Renderer in `src/ui/roomlayout/` (DOM or plain canvas, no new library): layers floor → wall → shadow → furniture →
  avatar → overlay; integer zoom 1×/2×/3×; draws from a room layout object (tiles, items with key, tile x/y, rotation).
- Layered avatar compositor (body/hair/shirt by hash of `sub`, front/back views).
- State overlays and HTML name tags on hover/focus (style guide §6).
- A dev-only demo page that renders a sample room from fixture data (no API).
- Packing script `pnpm sprites:pack`: reads `assets/art/export/*.png` (export convention, style guide §8), computes
  anchors from the canvas size, and writes `public/sprites/office.png` + `office.json`; fails on unknown keys or wrong
  canvas sizes. Placeholder art is produced into the same folder first, then packed the same way.
- The packing script also reads `assets/art/sprite-map.json` (style guide §0, §8b): cuts each key's rect from its
  source sheet, scales it with nearest-neighbour, bottom-aligns it in the export canvas and packs it. Priority per key:
  `export/<key>.png` > sprite map > code-drawn placeholder. Missing keys fall back to the placeholder.

## Out of scope
- Layout API and DB columns (SIM-015.1). Editor (SIM-015.2). Final art (Ming, M-9).

## Acceptance criteria
- [ ] The validator accepts the placeholder manifest and rejects a manifest with an unknown key or an out-of-bounds frame.
- [ ] The demo page renders the sample room at 1×/2×/3× with crisp pixels (no smoothing) and every seat state.
- [ ] Replacing `office.png` + `office.json` with another valid pair changes the art without code changes.
- [ ] Avatar colours are stable for the same `sub` and differ across sample subs.
- [ ] Name tags appear only on hover/focus and are reachable by keyboard.
- [ ] Unit tests cover the manifest validator, the avatar colour hash and tile → pixel placement.

## Technical notes
- Files: `public/sprites/*`, `scripts/build-placeholder-atlas.*`, `src/lib/sprites/*` (pure: manifest types, validator,
  placement), `src/ui/roomlayout/*`.
- Reference: the "Simap Room Map" mockup artifact (code-drawn sprites, overlays, name tags) and style guide.
- Risks: keep sprite logic pure in `src/lib` (R1); keep the bundle small (atlas is one PNG).
